## U 盘虚标容量检测工具

- 新增 `usb_fake_capacity.py`（单文件、仅标准库、Windows）。子命令：identify / check / restore。
- 机型现状：D: = Disk 2 "Flash Disk 3.0" USB 250GiB exFAT；E: = Disk 3 "VendorCo ProductCode" USB 1953GiB exFAT。两者均为无品牌主控签名，E 盘 2TB 虚标嫌疑极高。
- 关键技术点：回读必须用 `FILE_FLAG_NO_BUFFERING`（ctypes CreateFileW + 4KB 对齐缓冲），否则命中 Windows 文件缓存会把虚标盘误判为正常（实测缓存读 263MiB/s vs 直读 20MiB/s）。
- 校验块大小对齐到 4MiB，避免无缓存读到 EOF 之外；每 128MiB 文件 fsync；状态存 %TEMP% 供 --resume 续测。
- 实测 D: 写入 11.6MiB/s、直读校验 20MiB/s，故 D 全量约 10 小时、E 全量 80+ 小时，只能长时间挂机跑。
- 恢复容量走 diskpart（clean + create partition size=真实容量×0.98 + format exfat），需管理员且必须 --yes。
- 初筛结果（--quick，各写校验 16GiB）：D: 与 E: 均通过，首个异常偏移 null，结论 PARTIAL。
  D: 16/250GiB（6.4%）通过；E: 16/1953GiB（0.8%）通过，E 盘仍属高度不确定。
- 实测稳定写入 12.7MiB/s、直读校验约 20MiB/s；推算 D 全量约 9 小时、E 全量约 72 小时。
- 注意：Bash 的批量删除安全阈值约 30~50 个/次，脚本收尾删 128 个测试文件会被拦，需另行分批清理（已用 Python 分批删净，两盘现只剩 System Volume Information）。
- 报告文件：usb_capacity_report_D.json / _E.json（含建议分区大小 MB）。

## 快速探测方案（usb_quickprobe.py）

- 需求：用户要“更快捷的方法，允许三方开源工具”。核心结论：顺序写满是唯一“证明”，但映射型假盘可用**随机扇区别名抽样**秒级定性。
- 新增 `usb_quickprobe.py`：ctypes 裸盘（\\.\PHYSICALDRIVE + FSCTL_LOCK_VOLUME/DISMOUNT），向 512 个随机 4KiB 扇区写唯一标记后回读；某扇区读回别人的标记即证明地址映射；对碰撞位置差取 gcd 反推真实容量。
- 关键常量：SECTOR=4096（同时满足 512/4096 物理扇区对齐）、SKIP_HEAD=32MiB（跳过引导/元数据）、FILE_FLAG_NO_BUFFERING|WRITE_THROUGH。
- 环境限制（重要）：本机 WSL 被安全策略列入程序黑名单无法调用；当前会话无管理员权限，连 `\\.\PHYSICALDRIVE` 只读都返回 error 5。故该脚本只能交付、无法代跑，仅 dry-run（回退到 PowerShell 上报容量）验证通过。
- 备选现成工具：f3probe/f3fix（GPLv3，Linux/WSL 裸盘，几分钟出真实容量）、ValiDrive（GRC 免费 GUI）、ChipGenius（读闪存 ID 判标称是否匹配）；真正改回上报容量需主控量产工具（MPTool），diskpart/f3fix 只能缩小分区。

## E 盘快速探测实测结果（用户以管理员自行运行）

- `usb_quickprobe.py --letter E` 结果：514 抽样中 501 异常、13 一致 → 判定 FAKE。
- 关键发现：501 个异常扇区读回的都不是任何标记（src=null），说明该主控（VendorCo）**不是回绕型，而是超容量写入直接丢弃**，因此 gcd 反推失效（推算真实容量为 null）。
- 数据推算：上报 2,097,152,000,000 B = 512,000,000 扇区；首个异常 LBA 17,938,335 → 硬上界 73.48 GB / 68.44 GiB；命中率 13/514=2.53% 点估计 53.1 GB。综合判断真实容量 53~68 GB，最可能 64 GB 级。
- 脚本增强：新增 `--locate` 二分定位（利用"丢写"特性单调性，约 29 次单扇区探测出精确边界）；报告新增 最大成功LBA / 首个异常LBA / 异常LBA列表(200) / 容量硬上界 / 估算方法。
- 教训：报告若只存前 20 条异常，缺"最大成功LBA"就无法精确界定区间；已在报告中补记。
